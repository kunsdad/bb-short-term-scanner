# BB Scanner v0.3 (시험용)

## 적용
기존 저장소 최상위 `scanner.py`를 교체하고 `dashboard.py`를 추가합니다. `requirements.txt`는 기존 파일과 비교 후 갱신합니다. `.github/workflows/daily_scan.yml`은 ZIP의 `daily_scan.yml` 내용을 해당 경로에 반영합니다. **ZIP 자체를 업로드하지 마세요.**

## 실행
`pip install -r requirements.txt` 다음 `python -u scanner.py`.
대시보드 로컬 실행: `streamlit run dashboard.py`.

## 변경
- `data/history.sqlite`에 최근 200거래일 종목별 데이터를 캐시하고 최근 14일 구간을 다시 받아 보정합니다. 첫 실행은 전체 과거 데이터를 받으므로 시간이 걸립니다.
- 동시 요청 4개(환경변수 `BB_WORKERS` 1~6), 요청 실패 1회 재시도. 속도 개선은 실제 실행 결과로 검증해야 합니다.
- 가격/거래량 이상 및 거래정지 추정 종목 제외, 제외 종목을 `data/skipped.json`에 기록합니다.
- 손절가 0원 방지, 목표가가 없는 경우 신규 후보에서 제외합니다. 목표가는 5일/20일 이동평균선 상방 저항만 사용하며 매물대는 미구현입니다.
- 최신 데이터 날짜가 다른 종목은 신규 후보에서 제외합니다.
- `dashboard.py`는 결과를 읽어 필터/검색합니다. 별도 웹 호스팅 배포는 아직 수행하지 않았습니다.

## 주의
- 현재 업종 상대강도 미측정, 10점 만점 전체 체계 미완성입니다.
- 최신 날짜는 수집 데이터의 최댓값으로 판정합니다. 공식 KRX 거래일·휴장일 확인, 무료 데이터 공급원 갱신 시각 검증은 아직 미구현입니다.
- GitHub Actions 일정 실행은 지연될 수 있습니다. 휴장일에는 새 데이터가 없을 수 있습니다.
- `history.sqlite`는 Git에 커밋되므로 저장소 용량이 증가합니다. 장기 운영 시 캐시를 별도 저장소/아티팩트로 이전하는 편이 좋습니다.
- 점수는 기존 v0.2 기준을 유지하되 **상방 목표가가 없는 경우 후보 제외**를 추가했으므로 결과가 달라질 수 있습니다.
